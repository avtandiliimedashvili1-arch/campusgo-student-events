# PRD — CampusGo

## 1. პროდუქტის მიმოხილვა

**პროდუქტის სახელი:** CampusGo  
**ტიპი:** სტუდენტური ღონისძიებების საძიებელი ვებ-პროტოტიპი  
**ვერსია:** 0.1 (შუალედურის პროტოტიპი)

CampusGo მიზნად ისახავს სტუდენტს დაეხმაროს შესაბამისი ღონისძიებების აღმოჩენაში ისე, რომ ღონისძიებების შესახებ ინფორმაციის მოძიება სხვადასხვა არხზე არ დასჭირდეს. ამ ეტაპზე ეს არის დიზაინისა და გამოყენებადობის სადემონსტრაციო პროტოტიპი, არა ცოცხალი ღონისძიებების ბაზა.

## 2. პრობლემა და მომხმარებელი

**პრობლემის ჰიპოთეზა:** სტუდენტებისთვის უნივერსიტეტთან დაკავშირებული, საგანმანათლებლო, კარიერული და კულტურული ღონისძიებების ინფორმაცია შეიძლება სხვადასხვა სოციალურ გვერდსა და ჩატში იყოს გაფანტული. ამის გამო მათ შეიძლება უჭირდეთ შესაბამისი ღონისძიების დროულად აღმოჩენა და დამახსოვრება.

**სამიზნე აუდიტორია:** უნივერსიტეტის/კოლეჯის სტუდენტები, რომლებსაც აინტერესებთ პროფესიული განვითარება, ტექნოლოგიები, კულტურა და ახალი ნაცნობობები.

**მნიშვნელოვანი შენიშვნა:** ეს არის დასადასტურებელი ჰიპოთეზა. კვლევის შედეგების სექცია შეივსოს რეალური გამოკითხვის ან ინტერვიუს შემდეგ; ჰიპოთეზა არ უნდა იყოს წარმოდგენილი დადასტურებულ ფაქტად.

## 3. მომხმარებლის საჭიროებები

- მინდა ერთ ადგილას ვნახო ღონისძიებების სია.
- მინდა სწრაფად მოვძებნო სათაურით ან თემით.
- მინდა კატეგორიით გავფილტრო ვარიანტები.
- მინდა საინტერესო ღონისძიებები შევინახო და მოგვიანებით ვიპოვო.
- მინდა დეტალების ნახვა გვერდის დატოვების გარეშე.

## 4. MVP-ის ფარგლები

### ჩართულია

1. **ღონისძიებების სია:** ბარათები სათაურით, კატეგორიით, თარიღითა და ადგილით.
2. **ძიება:** სათაურის, აღწერის, თემისა და ადგილის მიხედვით.
3. **კატეგორიის ფილტრი:** ყველა, ტექნოლოგიები, კარიერა, კულტურა, ქსელინგი.
4. **რჩეულები:** დამატება/წაშლა; მხოლოდ რჩეულების ნახვა.
5. **დეტალების მოდალი:** აღწერა, თარიღი და ადგილი.
6. **რეაგირებადი დიზაინი:** ტელეფონი და კომპიუტერი.

### ამ ვერსიაში არ შედის

- ავტორიზაცია და მომხმარებლის პროფილი;
- საერთო backend ან მონაცემთა ბაზა;
- ღონისძიების დამატება/რედაქტირება;
- რეალური რეგისტრაცია, ბილეთის შეძენა ან გადახდა;
- ელფოსტით/SMS-ით შეხსენება;
- დამოწმებული რეალური ღონისძიებების მონაცემები.

## 5. მომხმარებლის ძირითადი გზა

1. მომხმარებელი ხვდება მთავარ გვერდზე.
2. ათვალიერებს ღონისძიებებს ან წერს საკვანძო სიტყვას ძიებაში.
3. სურვილის შემთხვევაში ირჩევს კატეგორიას.
4. ხსნის ღონისძიების დეტალებს.
5. ამატებს ღონისძიებას რჩეულებში.
6. ზედა მენიუდან გადადის რჩეულებზე და ხედავს შენახულ სიას.

## 6. წარმატების კრიტერიუმები (MVP acceptance criteria)

- ძიება განაახლებს ხილულ ბარათებს აკრეფისას.
- კატეგორიის ფილტრი მუშაობს ძიებასთან ერთად.
- დეტალების ღილაკი ხსნის იმავე ბარათის სწორ დეტალებს.
- რჩეულების ღილაკი მუშაობს ბარათზეც და დეტალების ფანჯარაშიც.
- შენახული რჩეულები რჩება გვერდის განახლების შემდეგ იმავე ბრაუზერში.
- თუ შედეგი არ არის, მომხმარებელი ხედავს გასაგებ შეტყობინებასა და ფილტრების გასუფთავების გზას.
- გვერდი გამოსაყენებელია ვიწრო მობილურ ეკრანზეც.

## 7. მონაცემები და კონფიდენციალურობა

ღონისძიებების მონაცემები დემოა. მომხმარებლის პირადი მონაცემები არ გროვდება. რჩეულები ინახება მხოლოდ მიმდინარე ბრაუზერის `localStorage`-ში; ისინი სხვა მოწყობილობაზე არ სინქრონდება.

## 8. ტექნოლოგია და გამოქვეყნება

- Frontend: HTML5, CSS3, Vanilla JavaScript
- Local persistence: `localStorage`
- Version control: GitHub
- Static hosting: GitHub Pages

არჩეული სტეკი მინიმუმამდე ამცირებს კონფიგურაციას და გვეხმარება დროის შეზღუდვაში ფუნქციური, Live დემოს მიღებაში.

## 9. რისკები და მომდევნო ნაბიჯები

**რისკები:** კვლევის მცირე ნიმუში ვერ განზოგადდება ყველა სტუდენტზე; დემო ღონისძიებები არ ასახავს ცოცხალ მონაცემებს; რჩეულები მხოლოდ ერთ ბრაუზერში ინახება.

**შემდეგი ნაბიჯები:** კვლევის შედეგებით პრობლემის დაზუსტება; სტუდენტებთან გამოყენებადობის მოკლე ტესტი; რეალური ღონისძიებების წყაროს შემოწმება; საერთო ბაზის ან ორგანიზატორის დამატების ფუნქციის შეფასება მხოლოდ MVP-ის შემდეგ.
